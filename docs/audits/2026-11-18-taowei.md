# 韬普教育云阅卷适配审计

关联 Issue #519。适配入口为 `yj.taoweiedu.com` 选择年级、科目后的 s1 至 s6 站点，普通单题阅卷页为 `/web/mark/sjpy/sjpy_kspy.jsp`。

## 现场依据

同账号进入高二语文作文的 2+1 评阅任务。原生题目满分60、步长1，给分点一个，答卷包含两个题块图片。iframe 的 src 属性仍保留 navi.jsp；实际文档已导航到单题页，因此按实际窗口地址检测。原生脚本中的取题、得分点构造、图片路径、分数验证、提交倒计时、确认和保存回调均已读取。

本机原始页面、平台资源、图片及截图保存在 Core 仓库外的 LocalPlatformScenes/taowei/2026-11-18。仓库只包含构造的题目、答卷身份与练习图片。

## 数据流

| 环节 | 约束 |
| --- | --- |
| 平台与题目 | 严格匹配 s1 至 s6 域名、同源 iframe 实际地址及原生考试、科目、试题；题目标识不包含学生卷号。 |
| 当前给分点 | 原生题目、标签、数量、逐项满分、合计、DOM 控件及步长互相核对。两张图片不会被解释为两个评分项。 |
| 答卷图片 | 全部题块加载完成，按顺序核对当前任务、卷号和区域；排除整图预览、其他卷、外部来源和未完成图片。 |
| 模式 | 普通单题键盘给分，支持单评、双评和2+1评；原生回评、试评、仲裁、检测卷及其他给分方式交教师在原站核对。 |
| 写分 | 全量检查数量、空槽、数值、满分及档位后才写入；每次事件复查答卷，最后核对原生输入值和控件。任何失败都不能产生可提交记录。 |
| 倒计时与确认 | 等待原生按钮恢复；只点击与本卷、本轮分数一致的原生打分确认按钮。取消、换卷、改分或其他对话框均不自动确认。 |
| 保存 | 再次核对本卷、本题、模式、控件、图片以及原生 POST 的全部评分字段。观察 HTTP 成功和布尔 res=true；不明结果暂停，不重发。 |
| 换卷 | 只接受已确认保存的基准；同题的新答卷身份和全部题块连续就绪后才继续。分数框清空和缓存更新不作换卷证据。 |

## 实测与回放

实际账号验证了页面识别、两个原始 JPEG 下载、原生60分给分点、超分拒绝、零分写入、打分确认及 pycs=3 的请求构造。保存请求通过浏览器请求拦截返回拒绝回执，确认助手按未保存处理；请求没有发往真实保存接口。测试后原输入及确认设置恢复，同一答卷保持不变。真实成绩的最终提交由教师完成。

构造回放使用真实页面的数据契约，验证成功与拒绝回执、当前答卷关联、取消、倒计时、零分确认、分项完整性和新答卷就绪。完整 bundle 在1280及420宽度、深浅色下执行双页答卷、给分点和保存链路检查。平台多给分点以构造数据验证；本次真实任务是一个作文给分点。

发布依据为本提交的完整单元、构建、bundle、浏览器和内部 CI 回执；实际账号结果与构造回放分别记录。

## 核心校验联动

关联 Issue #525。题目信息独立于答卷加载及提交状态读取，仅当前已核对的原生确认允许读取答卷身份。核心开启题目校验时，确认窗口和保存后加载新卷均保留同题基准；取图与写分仍要求当前答卷完整就绪。联合回归直接执行核心 runtime 与答卷校验函数，核对零分确认，以及原生回调先清空答卷再触发保存回执的顺序。
