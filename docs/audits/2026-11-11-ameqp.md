# AMEQP 连续阅卷与答卷标识审计

审计日期：2026-11-11。代码版本：1.21.19.6。

## 反馈与适用版本

[Issue #362](https://github.com/five-plus-one/AI-Marker-Suite/issues/362) 反馈稳定版 1.21.19.0 在平台已显示后续答卷时仍反复等待。正文提供了旧版等待函数的代码分析，没有实际换卷前后的图片地址、诊断日志或新版复现结果。因此，相同的页面现象可以确认，具体部署是否存在恒定卷号仍需现场证据。

稳定版与预览版的代码不同。[PR #356](https://github.com/five-plus-one/AI-Marker-Suite/pull/356) 已把等待基准移到提交前；[PR #359](https://github.com/five-plus-one/AI-Marker-Suite/pull/359) 增加了给分事件之间的答卷检查。这两项进入了 1.21.19.5-preview.103。

## 根因与复现

### 平台先换卷，脚本后开始等待

稳定版提交函数点击原生按钮后等待 800ms，随后等待函数才读取当前卷号。如果原生按钮已把 A 卷换成 B 卷，等待函数把 B 当作旧卷，从而等待没有触发的 C 卷。即使 A、B 卷号正常变化，也能触发该问题。

旧版每轮在第 101 次 200ms 检查时超时；三轮和两次 2s 重试间隔约 64.6s。Issue 对弱信号门控的观察符合旧代码，但不能据此断定真实卷号恒定。

对稳定版与 1.21.19.5 源码执行相同的同步换卷场景：稳定版返回未换卷，预览版立即识别下一份。此对照使用加速定时器验证逻辑，时间上限按源码计算。完整压缩脚本另在浏览器中以正常定时器连续提交三份，覆盖快速换卷和延迟换卷。

### 非标准地址的公共前缀

进一步构造 `scan_A_00_1_0.PNG`、`scan_B_00_1_0.PNG` 和查询参数选择图片的地址，发现 1.21.19.5 会把公共前缀当作可靠卷号。给分事件切换到同前缀地址后，后续写值或隐藏字段同步可能仍执行；最终返回失败不能撤销这些写入。这是新增的代码边界复现，未证明反馈人的部署使用这些地址。

### 首图与其他题块属于不同答卷

原有可靠标识只读取第一张作答图。其他题块先切到新卷、首图仍为旧卷时，填分和提交检查不能发现混合状态。新增用例覆盖给分事件中发生这种变化，以及登记完成后出现另一份答卷题块。

## 1.21.19.6 的处理

- 仅识别已在诊断中确认的 `数字考号_数字_数字_数字.图片扩展名` 格式；支持目录、缓存参数、大小写和 URL 编码变化。
- 核对全部作答图所属答卷，未知地址格式或不同卷号的题块不能提供可靠标识；取图、填分和提交均停止相应自动操作。
- 保留提交前基准、所有图片解码完成后继续、任务变化和取消等待、提交幂等及逐事件校验。
- 分数框清空、总分归零、仅刷新缓存参数均不单独证明换卷。核心层还会检查适配器报告的下一份是否仍为原卷，不能只放开等待函数中的弱信号。

此处理保护无法确认身份的答卷，不代表已适配所有使用固定图片入口的 AMEQP 变体。若平台把不同答卷放在完全相同的可靠标识下，仍需查明其原生答卷 ID 或其他明确的换卷信号，不能安全地凭空恢复自动连续阅卷。

## 验收与证据范围

新增单元回归在修复前出现 7 项失败，修复后 AMEQP 37 项通过；全量 601 项测试、126 项压缩脚本校验和 76 项浏览器用例通过。浏览器中的 20 项 AMEQP 用例覆盖快慢连续换卷、多题块连续换卷、未知地址和混合答卷的副作用检查，运行实际构建产物和匿名页面，使用虚拟 AI 响应。连续阅卷场景每次提交三份，未知地址及混合答卷场景核对 AI 请求、原生给分与提交均为零。

本地已有诊断中的图片地址符合上述已知格式；诊断未包含原生提交及换卷脚本的完整实现。本次再次访问内网阅卷地址超时，未实际提交学生成绩，不能据此宣称反馈人的现场问题已经复测通过。

Issue #362 应保留待核验状态。后续现场证据需要包含脱敏的换卷前后图片地址结构、实际安装版本，以及是否只改变查询参数、是否重用同一文件名等信息。不得提交学生姓名、考号、原始答题卡或登录凭据。
