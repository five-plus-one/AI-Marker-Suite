# 学生作答与参考资料归属审计

审计基线：稳定版 `v1.21.22.0`，预览基线 `450ccd8`，本次实现 `1.21.22.3`。

## 版本与需求来源

稳定版 `1.21.20.0` 至 `1.21.22.0` 没有对“无法辨认”设置专门暂停条件。解析得到分数后进入评分计算、填分和提交；无可解析分数时进入错误处理。

提交 `a86486a` 在预览批次 `1.21.22.1` 增加作答状态核对，对明确无法辨认的结果暂停。[问题 #395](https://github.com/five-plus-one/AI-Marker-Suite/issues/395) 报告本地 Qwen 模型在模糊作答上复述参考答案并给满分；报告中的纯空白样本得零分。这与智学网小题算式解析问题属于不同路径。当前无人模式按“重试、保留有效 AI 分数提交、待复核数量超阈值后暂停”处理。

## 请求资料来源

- 学生图片来自适配器 `gatherAnswerImages()`，经本轮上下文保存图片字节；教师题目、参考答案和评分标准的图片单独经 `collectFieldImages()` 收集。
- Markdown 字段只发送正文实际引用的图片，兼容早期仅图片字段。已删除引用的参考图不继续进入请求。
- `callAIOnce()` 保持参考图片和学生图片两组来源，逐图添加用途标签。尺寸过滤按原始索引处理，参考图片被剔除后，学生图片仍保留学生用途标签。
- 单评、双评双方和第三模型仲裁均以 `gradingRequest` 标识评分请求；有效学生图片为空时，参考图片不能满足取图条件，请求直接失败。
- 教师纠错使用同一逐图标注。只有文字的历史纠错可以分析评分标准，其结果是教师确认的配置修改，不是无人阅卷分数。

## 空白与无法辨认

提示词要求仅对学生实际作答评分，排除印刷题干、预印图形和参考资料；整卷未作答给零分；有字但无法辨认与未作答分别标记。详细模式要求逐字转录及引用原始作答，精简模式保留作答状态。

程序核对模型明确报告的状态。未作答与正分冲突时停止；双评在合并前分别检查原始两侧，避免用主模型复述覆盖另一侧的结论。无人模式仅对明确无法辨认重试及记录待复核，不将空白正分或识别矛盾归入该通道。

模型如果把参考答案复述成学生答案、同时报告“可辨认”，上述状态核对无法证明其复述来自原图。提示词与用途标签可以降低此风险，不能证明任何视觉模型都不会发生这种错误。短答案、公式和选择题与参考答案完全一致属于正常情况，不能仅凭文本相似就判零分或停止。

## 平台取图范围

审阅构建注册的 43 个适配器的选择器与取图入口，重点追踪宽图片类名、通用 Canvas 选择器和原生图片池。多数图片选择器限定答题卡容器、答卷图片类名或原生接口。

- `haofenshuyize` 的 `gatherAnswerImages()` 收集整页 `.el-image__inner` 的 HTTP 图片，没有容器、可见性或学生标识筛选。平台其他区域若使用同类组件显示参考答案，该图存在一同进入学生图片列表的可能。需要带参考答案弹层的真实页面归档确认容器边界。
- `huahanyun` 虽以 `img.el-image__inner` 查询，但取图进一步检查可见性、图片尺寸、`/student/` 路径和同一考生标识；不能仅凭通用类名认定它与上一项相同。`hanhan` 实际取图使用 `.el-image.photo_bg img.el-image__inner`，选择器文件中的宽类名没有在该取图函数中启用。
- `lehua` 导出整页首个 `canvas`，尚缺答卷容器限定；参考资料或其他组件先创建 Canvas 时存在误选可能，需要真实 DOM 确认。`guangda-2` 和 `jiukexing-homework` 虽有通用 Canvas 页面检测，实际取图使用包号或学生/题目接口映射，不能据检测选择器推断它们导出任意 Canvas。

这些边界没有真实页面证据时，不能确认所有候选图片的归属。本次没有依据猜测收紧选择器；宽入口的现场验证与当前模型状态处理分别记录。

## 验证边界

回归检查实际请求载荷，覆盖缺图、学生图全部无效、混合参考图剔除、单评、双评和仲裁；主流程覆盖三种模式、详细和精简输出、未作答零分、空白正分冲突及无人待复核通道。提交失败不计进度，图像或记录保存失败不填分。

这些测试使用受控响应验证程序行为，不等于对真实视觉模型进行盲测，也不表示 43 个平台均已逐一登录实测。现有登录现场和私有答卷归档保留在本机，不进入仓库。
