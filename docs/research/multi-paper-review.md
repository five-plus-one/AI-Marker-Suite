# 同屏多卷阅卷

## 平台调研

智学网的同屏阅卷以题目为单位，老师选中一份或数份答卷后统一赋分。批量打分设置调整排列，单次发卷量由考试配置决定。历史页面副本的批量阅卷引导与给分逻辑一致。离线执行选卷、给分及保存成功处理时，2 分和 0 分分别作用于选中的答卷，未提交的答卷留在当前页。正式场次中的保存响应、最后一组换批、回评、配额及错误分支以独立测试场次为准。用户提供的完整现场截图保存在工作区的受限证据目录。

| 场景 | 接入条件 |
| --- | --- |
| 平台每次发一份答卷，同一份答卷有多张切图 | 使用已有单卷流程，适配器提供该卷所有切图 |
| 平台一次展示多位考生的同题作答，选中后按分组给分 | 适配器提供每份独立答卷与可核对的给分、保存操作。智学网属于此类 |
| 平台每份有独立分数栏，允许一批保存 | 适配器提供卷与输入栏的确定关系。可沿用按分值分组保存，也可在明确支持时一次保存异分结果 |
| 多位教师分别批阅同一题，平台每次只给当前教师一份 | 继续采用平台分配规则。客户端以当前教师可编辑的答卷为准 |
| 同一组浏览器中出现两种阅卷模式 | 启动时先识别模式。批量模式载入中或状态未知时，在页面就绪后重新识别 |

公开参考 [智学网帮助中心](https://help.zhixue.com/help/) 与 [湖南师大附中阅卷操作说明](https://www.hnsdfz.org/zhxy1/szxyczsm/content_5796)。

## 老师的操作

从「AI 批改」进入当前题目的批量批改。待处理答卷按原顺序排列，识别完成即补上建议分和依据。教师可查看切图、改分、选择需要确认的答卷，或处理待核对项。确认页显示本次各分数档的份数，确认后使用平台的给分和提交操作。处理完成后显示已保存份数和待处理项。平台加载同一道题的后续一批时，可在同一工作区继续。

## 适配器与运行约定

- 批量能力独立于单卷入口。判断批量模式需要平台明确线索。适配器单独提供当前题标识、分值约束、答卷标识、切图依据和给分就绪状态。
- 答卷标识来自平台分配，切图依据依据稳定的作答来源生成。两者都要匹配；显示序号、区块位置、缩放和临时签名用于展示或取图。
- 同一题使用已保存的评分方案。每次评分只接收一份答卷的切图，复用既有单评、双评和分数计算。并发有上限，失败保留在该卷，可以重试。模型的未识别、弃权和无分结果转入待核对。
- 确认锁定答卷、切图依据和分数。提交前重新读取平台，按评分组依次写入。平台状态确定后才前往下一组。适配器报告已保存、尚未派发或保存状态待核对。保存状态待核对时，保留结果，停止后续给分，并由老师查看平台阅卷记录。
- 切题、换账号和退出工作区停止发起新的评分或给分。在途操作按各自的状态处理。部分提交后仍可核对尚留在同一题的答卷。同一平台的教师权限、复评、配额与任务流转由平台决定。

## 验收范围

| 范围 | 预期 |
| --- | --- |
| 单卷入口、常规换卷和小题评分 | 继续使用相同入口与平台流程 |
| 乱序返回、请求失败、取消和重试 | 各结果只进入对应的卷，失败项可单独恢复 |
| 评阅中手动切题、切批、选卷、改原生分数或开启自动提交 | 过期数据不能用于给分，教师已有的原生操作保留 |
| 0 分、半分、最高分、非法分数、空白卷、残图、答卷重排 | 只有匹配当前页面与评分方案的答卷可确认，0 分作为有效分值 |
| 确认名单期间其他卷返回，重复确认 | 原名单保持固定，同一组仅派发一次 |
| 已保存一组后另一组失败、超时、配额提示、末组换批 | 已确认保存的组单独标记，有疑义的组停在平台核对步骤 |
| 适配器独立接入 | 模型并发、结果和确认使用同一批量控制器，平台专属规则留在适配器 |
| 完整浏览器流程 | 使用已脱敏的样卷检查宽窄布局、深浅主题、键盘、触屏、实际给分和换批 |
