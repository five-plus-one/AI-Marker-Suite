# 七天网络评分适配审计

关联 Issue：#500、#502。适用页面：七天网络旧版 `yj.7net.cc/Review`，由 `qitian` 适配器处理。审计日期：2026-11-16。

## 现场依据

第15题答卷写明共14分、每空2分，共7个作答空。平台只提供一个总分框 `#tbs1`；其 `inputByKey(event,1,1,14)` 第四参数与同题行“满分”按钮的 `data-val` 均为14。作答空数量与平台评分框数量是两个概念。

反馈中的 AI 输出包含重复小题标签及未识别分数。空分应保留核对状态，不能补零或用不完整分项生成总分。当前参考答案页显示“答案未扫描”；助手已有参考答案与该化学题不匹配，教师仍需核对题目、答案和评分标准。

原始界面、配置、关联页面、图片、平台脚本和诊断日志保存在本地归档，带逐文件 SHA-256 与压缩包校验。源码和测试使用合成材料。

## 审计结果与实现

| 路径 | 结论与处理 | 验证 |
| --- | --- | --- |
| 原生评分单元检测 | 按可见评分框读取题号；每行可包含多个评分框。排除隐藏残留与其他输入框。 | 单框、不同满分的多框、隐藏框、非评分输入框。 |
| 满分来源 | 读取输入框 `max`、原生键盘处理器字面量及同题满分按钮；来源冲突时要求核对，未知值保留未识别状态。 | 单一来源、相同来源、冲突、缺失、跨行隔离及小数。 |
| AI 前配置核对 | 比较方案总分与原生满分，检查小题名唯一性；多原生框还核对题号顺序与各题满分。 | 沿用4分方案至14分题、重复标签、全半角等价标签、错位配置在请求模型前停止。 |
| AI 结果解析 | 复用现有完整分项解析；缺项或矛盾分数保持未识别，不从答案正文抓数字或补零。 | 七个分项完整与缺一项的真实主流程。 |
| 分数计算与填分 | 单总分框汇总全部有效分项；多框精确对齐数量，旧接口按题号匹配。写入前检查完整性、数值、范围与可写状态。 | 14分、0分、普通得分、空值、稀疏数组、非数值、溢出与分项数量不符。 |
| 原生控件与换卷 | 每次事件前复核题号、满分、控件、模式和答卷图片；填分后按预期数值读回。 | 控件被替换、页面改写非空分数、事件中换卷时停止后续操作。 |
| 提交前核对 | 只允许消费成功填分记录；提交前再次核对当前分数、答卷、题目与取消状态，同一记录只消费一次。 | 未填分、填分失败、改分、换题、换卷、只读、禁用及重复点击。 |
| 原生保存结果 | 通过原生提交按钮派发，核对同源 `POST /Review/guid` 的分数，并等待 HTTP 成功及明确的 `+OK` 协议回执。按钮点击本身不登记为保存成功。 | 成功、`-ERR`、错误页、HTTP失败、网络失败、超时、取消、旧轮次和请求分数不符。 |
| 请求观察生命周期 | 观察仅在本次保存期间生效；结束后恢复方法并移除监听，不将其他来源请求当作保存回执。 | 成功、失败、取消和超时后的恢复及其他来源请求保持原生行为。 |

## 验证方式

- `npm test` 覆盖七天适配器、真实批改主流程及现有跨平台回归。
- `npm run build -- --channel=dev` 与 `npm run verify:bundle` 检查构建与适配器注册。
- `node scripts/verify-browser.cjs --fixture=qitian` 在1280和420宽度、深浅色下，每种组合验证27项行为；包含原生 XHR 成功和拒绝保存。
- 浏览器验收使用隔离配置与合成页面，整个网络由测试程序拦截，保存请求由合成回执响应。
- `npm audit --audit-level=low` 与 CI 的 policy、compat 测试检查依赖及构建入口。

具体结果以 PR 当前提交的 CI 记录为准。

## 验证边界

生产答卷的提交由教师完成，本次没有向生产系统提交真实成绩。保存协议依据归档的平台 `reviewer.js`、`uri.js` 与合成回放验证；不明确的回执会进入人工核对。原站高低分确认弹窗保留人工确认，等待超过25秒仍未确认保存时停止自动流程。

此次范围为旧版七天页面；`qitian-new` 使用独立适配器。参考答案的学科与内容是否正确仍需教师核对，分数结构检查不替代内容判断。已发送到平台的原生请求无法通过取消操作撤销，取消会停止后续自动登记和继续改卷。
